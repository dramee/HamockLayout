# HammockLayout — выделение гамаков в ориентированном графе

Реализация на C++17 алгоритма из статьи
**В. Н. Касьянов, «Выделение гамаков в ориентированном графе»**, Доклады АН СССР, 1975, т. 221, № 5, с. 1020–1022.
Графы читаются из файлов **GraphML**. Внешних зависимостей нет.

## Определения

*Граф программы* G = (X, Г): выделены вход и выход, нет дуг, заходящих во вход или исходящих из выхода,
через каждую вершину проходит путь от входа к выходу.

Непустое U ⊆ X — *гамак* с начальной вершиной p ∈ U и конечной q ∉ U, если

    Г⁻¹(U \ {p}) ⊆ U,   Г(U) \ U = {q},   p ∉ Г(q).

Дополнительно (в статье это подразумевается — без этого неверна лемма 4) выход графа не лежит в U,
а если в U лежит вход, то p — вход. Подробности — в [hammocks.hpp](include/hammock/hammocks.hpp).

## Алгоритм (теорема 2, O(n·m))

1. **M- и N-нумерации** — обход в глубину из входа: M — порядок включения вершины в путь,
   N — порядок, обратный порядку удаления из пути.
2. **L-нумерация** — вначале равна N; затем для p с L-номером 1, 2, …, n строится S(p) — вершины,
   из которых p достижима без вершин с меньшим L-номером, — и эти вершины ставятся сразу после p.
3. **Перечисление гамаков** — для каждой p рассматриваются множества вершин с L-номерами
   Lp, Lp+1, …, Lp+k−1 (лемма 4). Величины K, R, E, F обновляются при добавлении каждой вершины,
   а критерий леммы 5 определяет, является ли множество гамаком и какой у него конец.

Для проверки есть эталон `findHammocksReference` за O(n²·m): для каждой пары (p, q) кандидат —
множество вершин, достижимых из p без прохода через q.

## GraphML

Читается первый `<graph>` документа. Вход и выход определяются так:

1. параметры `--entry` / `--exit` (`GraphMLOptions` в API);
2. данные вершин: ключ с `attr.name="role"` и значением `entry` / `exit`,
   либо логические ключи с `attr.name="entry"` / `attr.name="exit"` (учитывается `<default>`);
3. по степеням: единственная вершина без входящих дуг — вход, без исходящих — выход.

```xml
<graphml xmlns="http://graphml.graphdrawing.org/xmlns">
  <key id="role" for="node" attr.name="role" attr.type="string"/>
  <graph edgedefault="directed">
    <node id="a"><data key="role">entry</data></node>
    <node id="b"/>
    <node id="c"><data key="role">exit</data></node>
    <edge source="a" target="b"/>
    <edge source="b" target="c"/>
  </graph>
</graphml>
```

Данные из чужих пространств имён (например, графика yEd) игнорируются, кратные дуги склеиваются.
Неориентированные дуги, гипердуги и вложенные графы отвергаются с понятной ошибкой.

## API

```cpp
#include "hammock/graphml.hpp"
#include "hammock/hammocks.hpp"

hammock::Graph g = hammock::loadGraphML("graph.graphml");
hammock::HammockResult r = hammock::findHammocks(g);   // бросает GraphError для некорректного графа
for (const hammock::HammockSpan& h : r.spans) {
    std::vector<int> vertices = r.members(h);           // вершины в порядке L-номеров
    // g.id(h.start), g.id(h.end), ...
}
```

## Тесты

`tests/` — собственный мини-фреймворк, запуск `build/hammock_tests [фильтр]`:

* `test_xml.cpp` — XML-парсер: сущности, CDATA, комментарии, DOCTYPE, пространства имён, ошибки с номерами строк;
* `test_graphml.cpp` — чтение GraphML (роли, ключи по умолчанию, yEd/networkx-файлы, ошибки), запись и обратное чтение, проверка графа программы;
* `test_numbering.cpp` — M-, N-, L-нумерации на разобранных вручную примерах и их свойства на случайных графах;
* `test_hammocks.cpp` — гамаки на примерах с известным ответом (цепочка: n(n−1)/2 гамаков, как в замечании статьи; if/else, циклы, неприводимый граф, вырожденные случаи определения);
* `test_random.cpp` — сравнение с полным перебором всех подмножеств (до 14 вершин) и с эталоном O(n²·m) на тысячах случайных и структурированных графов, независимость от порядка вершин и дуг, проверка леммы 4.
